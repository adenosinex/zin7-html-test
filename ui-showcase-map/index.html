访问控制

  • 直达码两档：项目码（一项目一把，只开对应低等级项目）、全局码（一把，账号登录或可信设备静默登录时发放，通全部项目）；以 cookie 存浏览器，30 天。
  • 无码或过期：Caddy 302 到面板 /hub/enter——有面板会话则静默发全局码跳回；有旧的项目网关 cookie 则静默换发项目码跳回；都没有才走登录或弱口令门。全程自动，用户无感。
  • 等级三档：low（项目码或账号都可进）、console（只认全局码或账号，如 vidlib、docsnew）、open（无码直达，主要是 html 项目）。
  • 直达码（现行）：debi 全局码 + 18 把项目码为当前轮换后的一套；无感换发经 /hub/enter 跳板（已登录会话、信任设备、持弱门 cookie 三类用户均静默换发，零弱验证、零登出）；shoc 独立一套、互不关联；轮换前值备份在面板数据目录（0600，仅盒上）。
  • zin7 系入口登录优先（现行行为）：zin7.de 各域名（含 pys）下无会话/设备凭据时，项目被 Caddy 弹到 /hub/enter 后先跳控制台登录（平台级密码一次登录、静默发全局码、全项目直达），不再逐项目弹弱门；

平台内部服务规范（用户裁定）

  • 端口契约：平台内部服务都在本机运行、各自监听自己的端口；服务之间协作时，直接调用对方的 localhost 端口 API 即可——跨服务的唯一合法接触面就是端口契约。
  • 内部免验证：localhost 面上的内部调用不加验证（不带令牌、不查会话）；验证只存在于对外面，经面板、公网域名、客户端通道进入时照旧；本机可达即信任，与「验证只在平台层、项目内不设验证」的既有口径一致。
  • 禁止直接接触：不许读其他服务的代码目录与数据目录、不许借用对方的二进制、不许读对方的凭据文件、不许直连对方的数据库；需要对方的能力就调它的端口；对方没有这个端口能力，就给对方补 API，或者把功能收回自己项目内实现，不许伸手进去拿。
  • 目的：直接接触会把两个项目焊在一起——对方改目录、换工具、轮换凭据，都会无声地打穿本方，项目越长越复杂、越难拆；功能内聚在各自项目内，跨服务只剩一层薄契约，是低耦合高内聚在本平台的落地形态；与上文单向依赖原则同源（单向原则管「谁依赖谁」，本规范管「怎么接触」）。
  • 适用与准入：适用于全部现存与新增内部服务；新服务上架自检一句：「我只调端口，不碰任何其他服务的代码与数据。」；存量对照盘点（违规 / 合规 / 待裁逐项，含证据点）见用户工作区 your_files/平台内部服务规范与存量对照-20261110.md。
  • 备份同步口径：备份同步依赖共同规范（平台定标准导出规范、同步程序按规范通用收集）为主干；应用自报告（项目在自己数据目录放 backup-export.json 声明可备份物，同步程序按声明收集）是预留的特殊口子，不作通则；agy-chat-adapter 内部令牌已按规范去除，适配器回环免验证。
