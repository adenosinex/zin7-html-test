RECOMMENDATIONS · 10

最建议优化的四个点

1
关闭浏览器安全 DNS
尤其是 Chrome 和 Edge 的"使用安全 DNS"选项。这是 .73 设备大量 SYN_SENT 堆积的直接原因。关闭后，浏览器会直接使用系统 DNS（223.5.5.5），连接立即恢复。
2
代理统一 DNS
不要让浏览器 DoH、系统 DNS、Clash DNS、VM DNS 同时存在。选择一个 DNS 策略统一使用，避免"多层 DNS 冲突"导致的延迟和 SYN 堆积。
3
Hyper-V 用 Default Switch NAT
不要桥接。桥接模式会导致额外的 IPv6 地址和路由冲突，加剧"半残 IPv6"问题。使用 Default Switch 的 NAT 模式更稳定。
4
如果仍卡顿：临时禁用 IPv6 测试
你明显存在 IPv6 半通状态——有时通有时失败，每次失败都多等一轮超时。临时禁用 IPv6 可以立即排除这个变量，确认卡顿是否由此引起。
一句话总结
网络安全无问题，网络健康无过载。唯一的性能瓶颈来自 DNS/IPv6/DoH 三层路由策略不统一——关掉浏览器安全 DNS + 统一 DNS 策略 + 禁用 IPv6 测试，大概率能解决你感知到的所有"卡顿"。

不是入侵，不是木马，不是攻击。只是 DNS 层的"各自为政"。
